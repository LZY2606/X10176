# 谱峰案卷 · Peak Dossier

面向分析化学实验室的 centroid 质谱峰案卷系统：导入 m/z、强度、扫描时间、极性，围绕目标峰生成
同位素簇与加合物候选，并以**有版本的分支**管理观测、质量校准、基线、候选规则与人工裁定。
Kotlin + Ktor + SQLite，全部文件与数据都留在项目目录。

## 运行

需要 JDK 17（`./gradlew` 自带 Gradle wrapper）。

```bash
./gradlew build -x test                 # 仅构建
./gradlew test                          # 运行全部 15 个测试
./gradlew run --args='--host 127.0.0.1 --port 5236'
# 打开 http://127.0.0.1:5236 ，页面标题与正文均含“谱峰案卷”
```

首次启动会自动播种：根版本 + 初始校准/基线/规则 + 一份演示导入（含 2 行损坏扫描）。
SQLite 数据库位于 `data/peakdossier.db`（可用 `--db` 覆盖路径）。

## 领域设计要点

- **峰的稳定身份**：键 = 极性 + 规范化 m/z(1e-6) + 扫描时间(1e-4)；强度变化不改变身份，
  重新导入相同峰不会产生重复峰。
- **候选解释**（不只是化合物名+总分）：每个候选附带使用到的观测峰键、单同位素 ppm/Da 误差、
  每个同位素位的理论/观测 m/z、ppm、Da、间距(×z)、观测/期望丰度比，以及规则版本与校准版本。
- **缺失同位素 ≠ 冲突**：期望丰度低于噪声的同位素标记为“未期望”；高于噪声但未观测到才计为
  缺失，且绝不与“多个候选争用同一峰”混为一谈。
- **裁定前检查**：峰占用、荷电数、极性、保留时间窗口。峰争用返回**最小共享峰集合**。
- **版本分支**：导入、校准修订、校准回滚、基线、规则升级、污染标记、过饱和峰拆分、裁定都是
  追加在父版本之后的新版本；动作只影响从该版本继续的分支，旧版本可随时回看。
- **并发裁定**：请求带 `baseVersion`；若已不是分支头则返回 `409 VERSION_CONFLICT`
  （两个编辑者基于同一旧版本裁定时触发）。
- **新旧比较**：`/api/compare` 区分 OBSERVATION（导入/标注）、CALIBRATION、RULES 三类原因。
- **批量部分失败**：损坏扫描行进隔离区并保留逐行错误，其余扫描照常入库；导入整体在一个
  SQLite 事务中提交，服务中断不会留下半条版本或裁定。

## 接口

| 方法 路径 | 说明 |
| --- | --- |
| `GET /api/versions` / `GET /api/head` | 版本分支树 |
| `POST /api/ingest` | 粘贴 CSV/TSV 峰表（支持中、英、`m/z` 等表头别名），部分失败隔离 |
| `GET /api/imports/{id}/errors` | 某次导入的逐行错误 |
| `GET /api/view/{version}` | 该版本上的观测峰、校准、候选、证据链、冲突 |
| `POST /api/annotations` | 标记污染 / 拆分过饱和峰（产生新分支） |
| `POST /api/calibration` / `/api/calibration/rollback` | 校准修订 / 回滚到旧校准 |
| `POST /api/baseline` / `POST /api/rules` / `GET /api/rules/{v}` | 基线与规则版本 |
| `POST /api/adjudicate` | 接受/驳回（409 版本冲突，422 规则拒绝） |
| `GET /api/history/{version}` | 裁定历史 |
| `POST /api/compare` | 两个版本候选差异与归因 |

## 前端

单页 `app/src/main/resources/web/`：谱图滚轮缩放/拖拽平移/双击复位/点击峰查看、候选同位素
叠加、冲突队列（最小共享峰集合）、裁定历史、分析分支版本树，以及版本比较结果。

## 测试覆盖

`ppm` 与绝对误差边界、相同 m/z 的稳定身份、共享峰冲突最小集合、缺失低强度同位素、
校准拟合/回滚、批量部分失败、标注只影响子分支、规则升级归因、两个编辑者基于旧版本裁定的
409 冲突、刷新后峰占用 422，以及失败裁定不产生半条记录。
